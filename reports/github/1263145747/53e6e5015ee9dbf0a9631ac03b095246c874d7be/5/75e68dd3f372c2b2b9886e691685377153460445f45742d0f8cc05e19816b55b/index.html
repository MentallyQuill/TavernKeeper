JavaScript analysis reported javascript.xray.unsafe-regex

Expected behavior · medium confidence

The scanner saw text-matching patterns that, when written carelessly, can make a browser hang. These particular ones were written carefully: each has a hard limit on how much it can repeat, the choices inside cannot overlap, and the loops that scan text are capped. They only examine the user's own chat replies and error messages on the user's own machine. Even in a bad case, the extension would just be briefly slow, and nothing is shown that lets anyone outside the computer feed it harmful input.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The unsafe-regex signal is a static heuristic that flags repeated quantifier groups it cannot prove are linear. The visible patterns are engineered against catastrophic backtracking: every repetition is capped at a fixed maximum, the alternation branches inside the repeated groups match disjoint first characters (quoted runs versus non-quote characters, so there is nothing to backtrack between), and the tag-counting loops are explicitly capped by an iteration guard. These expressions run locally in the user's own browser over the user's own generated replies and provider error strings, entirely in service of the stated purpose of classifying how a reply ended. Even a worst-case pathological input would produce at most a transient local slowdown of the extension itself, which is a low-impact recoverable condition, and no input shown reaches these patterns from an attacker-controlled source. No data flow leaves the device, no destination beyond the host page exists, and no concrete activation path to meaningful harm is demonstrated by the supplied evidence.

Impact: none · Exploitability: unlikely

Developer action: none
