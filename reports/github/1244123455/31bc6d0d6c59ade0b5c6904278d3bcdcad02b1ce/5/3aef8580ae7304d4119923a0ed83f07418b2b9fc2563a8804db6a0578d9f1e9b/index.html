JavaScript analysis reported javascript.download-to-execution

Expected behavior · high confidence

A scanner paired a network request with a code-execution pattern in the same file and flagged it. In reality, the extension only asks the user's own SillyTavern server for the user's saved lorebook entries and pastes that text into the AI prompt. Nothing that is downloaded is ever run as code, and this is exactly the feature the extension advertises.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.download-to-execution. The match applies to this repository.

Contextual assessment: The flagged download-to-execution correlation is not supported by the actual data flow. The retrieval is a relative, same-origin request to the host SillyTavern server's world-info endpoint, carrying the host-provided request headers, and it is only a fallback used when the host context's own loading method is unavailable. The response is parsed as structured world-book data, cached in memory, and its entry text is inserted into LLM prompt content for scenario generation. No fetched content is passed to any dynamic evaluation sink, and the request never leaves the user's own server. This matches the documented world-info context feature exactly.

Impact: none · Exploitability: unlikely

Related contextual observations

Inconsistent escaping of entry identifier and dynamically built selection matching

low risk · medium confidence

The popup cleans most text before showing it, but two behind-the-scenes spots skip that cleanup. Because the data comes from the user's own setup and nothing harmful is shown to be possible, this is a tidiness and reliability issue rather than a danger.

Technical assessment

Nearly every user-visible value rendered from world book data passes through an HTML escaping helper, but the entry identifier is interpolated directly into an attribute in the entry markup, and book names are interpolated into dynamically constructed selector text used for book-level select and deselect actions. Both inputs originate from the user's own locally stored world info, so no attacker-controlled path or concrete harm is demonstrated. The gaps are hardening and reliability issues: unusual book names could break selector matching and behave incorrectly rather than cause any demonstrated security impact.

Impact: low · Exploitability: unlikely

Developer action: For consistency, pass the entry identifier through the same escaping helper used for neighboring values, and implement book-level selection by iterating rendered elements and comparing stored data attributes instead of interpolating names into selector text.
