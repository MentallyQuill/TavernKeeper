JavaScript analysis reported javascript.download-to-execution

Expected behavior · high confidence

The extension asks SillyTavern for the lorebook entries the user already has on their own machine and shows them in a picker dialog so the user can choose which ones to include in a generated scenario. It only talks to the local SillyTavern server, does not run or evaluate anything it receives, and properly sanitizes the displayed text. This matches the feature the extension advertises, and the automated scanner's warning is a false alarm from seeing both a download and interface-building code in the same file.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.download-to-execution. The match applies to this repository.

Contextual assessment: The flagged region contains a fetch to a same-origin SillyTavern endpoint that loads the user's own world info book entries, first attempting the host context's loadWorldInfo method and falling back to a POST to the local world info API with host-supplied request headers. The retrieved data is parsed as JSON and used only to build the world info selection modal; text fields are passed through an HTML escaping helper before insertion, and no dynamic evaluation, script injection, external destination, or persistence occurs. This is a direct, proportionate implementation of the project's documented World Info entry-picker feature, and the correlation between a network primitive and a DOM-building sink does not constitute a download-to-execution path. The unescaped entry identifier interpolation is a minor hygiene note at most, since the values originate from the user's own locally stored world books rather than an attacker-controlled source.

Impact: none · Exploitability: unlikely

Related contextual observations

World book entry identifier interpolated into HTML without escaping

low risk · medium confidence

Most of the text shown in the picker is cleaned before being added to the page, but the small identifier number for each entry is not. In practice these identifiers come from the user's own data and are safe, but cleaning them too would be a simple consistency improvement.

Technical assessment

When rendering each entry row, most text fields are passed through the HTML escaping helper, but the entry identifier is interpolated directly into a template string that is then appended to the document. World book entry identifiers are normally server-generated and not attacker-controlled, so this is not a demonstrated exposure; however, applying the same escaping to every interpolated value would make the rendering uniformly defensive against malformed or unexpected identifier values.

Impact: low · Exploitability: unlikely

Developer action: Apply the same HTML escaping helper to the entry identifier when building the entry row template.
