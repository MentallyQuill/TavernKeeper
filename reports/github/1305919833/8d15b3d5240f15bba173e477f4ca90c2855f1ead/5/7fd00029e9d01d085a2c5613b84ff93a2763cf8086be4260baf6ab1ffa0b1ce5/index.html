Related contextual observations

Save handler suppresses fetch errors without user feedback

low risk · medium confidence

If something goes wrong while checking or saving the raw record, the screen may stay quiet about it and the user's manual edit can be lost. This is a usability bug, not a security problem.

Technical assessment

The Raw JSON tab's save handler re-reads the current record to detect concurrent edits, and if that re-read fails the failure is swallowed and treated as if the record were unchanged. Similarly, an exception during the subsequent PUT is not caught, so the tab may not surface the failure state to the user. This is a local reliability issue only: the endpoints are same-origin, the failure mode is a confusing or lost manual edit within the user's own single-player session, and no attacker-controlled path or external data flow is involved.

Impact: low · Exploitability: unlikely

Developer action: Distinguish a failed freshness re-read from an unchanged record, and catch and surface PUT errors so the user knows their save did not land.
