The same family of anchored, bounded patterns appears throughout the supplied source for dates, times, and temperature tokens, and each operates on short, trimmed tag-attribute strings consistent with the extension's documented weather-tag parsing. No unsafe-regex condition is demonstrated despite the scanner signal, and no network, persistence, or execution behavior is associated with these parsers.

JavaScript analysis reported javascript.xray.shady-link

Expected behavior · high confidence

The scanner flagged what look like web addresses, but they come from data packed inside bundled weather artwork and from the standard labels browsers use when drawing graphics. Nothing here contacts the internet; the images are stored inside the extension file itself and drawn locally. This is a normal way to ship small artwork in a browser extension.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.shady-link. The match applies to this repository.

Contextual assessment: The flagged location is a bundled image asset: a base64-encoded PNG of a cloud sprite inlined as a data URI by the build step, with several more cloud sprites following. Address-like strings inside the flagged region are standard metadata namespace identifiers embedded in the image data and standard drawing-namespace identifiers used when creating inline vector elements for the animation layer. A data URI is rendered locally and does not perform a network request; the supplied windows show no fetch, network, or remote-destination code associated with these assets. The signal is a heuristic response to identifiers embedded in static image data, not demonstrated network access, and inlined weather sprites are proportionate to the stated HUD-and-ambience purpose.
