Related contextual observations

All flagged advisories appear to target build-time dev dependencies in a browser-bundle extension

low risk · medium confidence

All eight scanner flags point to development tools that help build the extension, not to the extension code itself. Since these tools are not shipped to users, the flags represent maintenance hygiene items rather than dangers to people using the extension.

Technical assessment

The root package in this lock file declares yaml as the sole runtime dependency. Every other declared dependency is a devDependency used for webpack bundling, linting, or type definitions. SillyTavern extensions are installed by cloning the repository and loading the bundled output in a browser context; node_modules and devDependencies are not part of the runtime attack surface. The scanner did not identify the specific package names for each advisory, so individual runtime reachability cannot be definitively ruled out, but the overall dependency structure provides no evidence of vulnerable code reaching end users.

Impact: low · Exploitability: unlikely

Developer action: Run a dependency update pass on devDependencies to clear the advisories, and consider adding an automated dependency audit step to the build workflow.

All flagged advisories map to build-time dev dependencies with no runtime reachability in the shipped extension

low risk · medium confidence

All the security warnings point to tools the developer uses to build the extension, not to the extension itself. When a user installs this extension, those build tools are not included, so the warnings do not represent a danger to users.

Technical assessment

The lockfile shows the root project declares only yaml as a runtime dependency. All other packages (eslint, webpack, ts-loader, css-loader, html-loader, style-loader, typescript-eslint, and their transitive dependencies) are devDependencies used solely for building the extension bundle. SillyTavern extensions are installed by end users as built artifacts; the dev dependency tree is not present at runtime. Therefore none of the flagged advisories have runtime reachability or attacker-controlled input paths in the user-facing extension. Confidence is medium rather than high because the scanner removed specific package names and the supplied lockfile source is truncated, preventing exact mapping of each advisory to a specific package version.

Impact: low · Exploitability: unlikely

Developer action: Run a dependency update pass on devDependencies to clear advisory flags and keep the build environment healthy. No urgent action is needed for the safety of extension users.
