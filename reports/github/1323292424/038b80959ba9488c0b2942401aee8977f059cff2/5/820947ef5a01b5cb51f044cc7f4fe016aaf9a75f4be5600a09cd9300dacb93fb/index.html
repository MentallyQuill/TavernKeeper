JavaScript analysis reported javascript.xray.unsafe-regex

Minor caution · medium confidence

The plugin uses many complex text-matching rules to parse chat messages. Some of these rules could theoretically slow down the browser if fed specially crafted text, but only on the user's own machine with their own chat content. The worst case is a temporary slowdown or frozen tab, not data loss or security breach.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The scanner flagged 19 unsafe-regex occurrences. The visible patterns are complex regular expressions used for parsing roleplay chat text, speaker cues, CSS snippets, and HTML scaffolding. Many use bounded lazy quantifiers such as [\s\S]{0,1400}? which limits but does not fully eliminate catastrophic backtracking risk on adversarial input. The input domain is the user's own chat session content in a local roleplay client. The worst concrete outcome would be a frozen tab or slowdown when processing a specifically crafted message—a local self-denial-of-service with low impact and no cross-user or system harm.

Impact: low · Exploitability: unlikely

Developer action: Consider testing the most complex regex patterns against pathological inputs and adding input-length guards or simplifying patterns that show significant backtracking.
