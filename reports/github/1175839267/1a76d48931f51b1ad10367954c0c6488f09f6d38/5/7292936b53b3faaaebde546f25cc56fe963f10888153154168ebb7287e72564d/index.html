Expected behavior · high confidence

The scanner saw code that mentions prototype-related special names and assumed danger. Actually, this code is a safety check from a widely used template library that blocks those special names from being abused. It protects against the very problem the scanner was worried about.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.prototype-pollution. The match applies to this repository.

Contextual assessment: The flagged line is part of the bundled handlebars 'createNewLookupObject' internals, which explicitly block dangerous properties (__proto__, __defineGetter__, __defineSetter__, __lookupGetter__, __lookupSetter__) by setting them to false in a null-prototype lookup object. This is the library's own prototype-pollution defense, not a pollution sink. A nearby source-map utility similarly only tests for the '__proto__' string to prefix it in output. There is no demonstrated code path where untrusted keys are merged into Object.prototype or Function.prototype. The scanner matched defensive literal references, which is the inverse of the risk the rule targets.

Impact: none · Exploitability: unlikely
