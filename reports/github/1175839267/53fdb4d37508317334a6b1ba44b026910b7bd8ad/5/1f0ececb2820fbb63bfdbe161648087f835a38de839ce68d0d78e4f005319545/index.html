OpenGrep reported tavernkeeper.dynamic-execution.javascript-eval

Minor caution · medium confidence

The scanner flagged the extension running template code on demand. That fits the project's purpose: templates are custom mini-programs users can author or import, and this feature runs a template's data-processing snippet when the template is active. The real concern is only that an imported template shared by someone else could contain unwanted code — but importing someone else's template already runs its script in the page when displayed, so this is a known consequence of the feature, not a hidden one. Contextual assessment: Detailed technical wording was omitted by the public report safety filter.

Impact: medium · Exploitability: plausible

JavaScript analysis reported javascript.xray.unsafe-regex

Expected behavior · high confidence

The scanner flagged some pattern-matching code as potentially slow. Looking at the actual code, these are the standard text-matching rules the bundled YAML library uses to recognize numbers, dates, and strings. They are simple one-pass checks, not the kind of pattern known to hang, and they only process the small tracker snippets the extension reads from chat messages. No actual slowdown or harm is shown.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The unsafe-regex signal flagged regular expressions in the bundled yaml library's stringifier and schema definitions. The supplied source shows the matched patterns are flat character-class tests and fixed-structure alternations for scalar type detection (plain-string safety check, timestamp, float, int, sexagesimal forms). None of the shown patterns contain nested unbounded quantifiers or ambiguous repetition that could produce catastrophic backtracking, and the inputs they run against are short tracker payloads embedded in chat messages. No demonstrated denial-of-service path or other concrete harm appears in the evidence; at worst this is a code-quality note inside a widely used parsing library that the project's documented YAML support requires.

Impact: none · Exploitability: unlikely
