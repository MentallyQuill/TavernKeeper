JavaScript analysis reported javascript.xray.unsafe-regex

Minor caution · medium confidence

Some pattern-matching expressions in the bundled libraries are written inefficiently. In the worst case a crafted chat message could make parsing slow on the user's own device, which is an annoyance rather than a security breach.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The flagged regexes come from the bundled YAML parser and template lexer: simple anchored alternations for recognizing booleans, numbers, floats, timestamps, and tokens. They operate on message content parsed locally by the extension. The shown patterns are bounded and lack the nested quantifier structure that typically causes catastrophic backtracking, and the worst plausible outcome from an inefficient regex over a chat message would be a temporary slowdown or a stalled tab on the user's own machine, which does not meet material harm.

Impact: low · Exploitability: unlikely

JavaScript analysis reported javascript.xray.unsafe-regex

Expected behavior · high confidence

The scanner flagged some text patterns (regular expressions) as possibly slow to evaluate. Looking at the actual code, these are standard pattern checks from a widely used YAML parsing library that the extension bundles to read tracker data. They are simple one-pass checks without the risky repeated-wildcard structure that causes hangs, and the evidence shows no scenario where an attacker could make them freeze a user's session.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The flagged signal originates in the bundled 'yaml' library's stringify and schema code inside the generated backend bundle. Reviewing the actual patterns in the supplied evidence: the scalar-type and number-format tests are simple anchored alternations over short, bounded character classes; the plain-scalar safety check is a flat alternation with no nested quantifiers; the folded-value replace uses bounded literal groups with a negative lookahead; the timestamp pattern is a linear concatenation of digit groups. None of these exhibit nested quantifiers, overlapping alternations, or unbounded backtracking structure characteristic of regular-expression denial of service. No attacker-controlled input path producing catastrophic evaluation is demonstrated, and even a pathological slowdown would be a self-recoverable local condition with low impact under the ecosystem threat model.

Impact: none · Exploitability: unlikely
