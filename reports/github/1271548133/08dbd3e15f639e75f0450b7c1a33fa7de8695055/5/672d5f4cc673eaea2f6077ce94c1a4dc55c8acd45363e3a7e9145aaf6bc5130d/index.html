Related contextual observations

Pipe-to-shell installer pattern in documentation warrants no finding on its own

low risk · high confidence

Running an installer straight from the internet is a common convenience, but it means users trust the project's website every time. Letting users download and read the installer first, or checking it against a published checksum, would be a nice extra, though nothing currently shown suggests any problem.

Technical assessment

The pattern of fetching a remote script and immediately executing it is a legitimate, disclosed, user-initiated installation method when the destination is the project's own distribution domain, as it is here. The evidence does not include the installer's contents, so any assessment of the installer itself is outside what this review can demonstrate. Best practice would be to also publish the installer in the version-controlled repository, provide checksums, or offer a two-step download-and-inspect instruction so users can review the script before running it, but the absence of those refinements is a documentation quality consideration, not demonstrated exposure.

Impact: none · Exploitability: unlikely

Developer action: Optionally publish the install script in the repository and link a checksum so users can verify it before executing; no security change is required by the supplied evidence.
