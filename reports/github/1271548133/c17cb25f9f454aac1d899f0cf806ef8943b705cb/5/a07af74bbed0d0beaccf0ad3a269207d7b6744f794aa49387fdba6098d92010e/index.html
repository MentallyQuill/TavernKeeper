OpenGrep reported tavernkeeper.download-and-execute.shell-pipeline

Minor caution · high confidence

The project's instruction page tells Linux server users to run one command that downloads and immediately runs an installer from the project's own website. This is a very common and openly displayed way to install software, not something hidden. The small downside is that the installer lives on the website rather than in the public code, and the instructions do not mention a way to check that the download has not been tampered with, so users must trust that the project's website stays secure.

Technical evidence

Scanner reason: OpenGrep matched static-analysis rule tavernkeeper.download-and-execute.shell-pipeline. The match applies to this repository.

Contextual assessment: The matched lines are documentation, not shipped executable code: the readme's server-installation section shows a single shell command that fetches an installer from the project's own website and pipes it straight into a shell interpreter. The instruction is fully disclosed, user-initiated, points only to the project's own domain, and is proportionate to the stated purpose of installing the application on a Linux server; this is a widespread installation convention and shows no concealment, unexpected destination, or malicious behavior. The residual weakness is supply-chain hygiene: the remotely served installer is not part of this repository, so its behavior cannot be audited from the supplied source, and the instructions document no checksum or signature verification, meaning users executing the one-liner rely entirely on the continued integrity of the project's web hosting. The readme does separately offer directly downloadable release artifacts, and no attacker-controlled trigger or untrusted-input path is present in the supplied evidence.

Impact: low · Exploitability: unlikely

Developer action: Consider publishing the installation script inside the repository so it can be reviewed with the rest of the source, and documenting a checksum or signature verification step, or guiding server users toward the verifiable release archives. This is a hygiene improvement, not an urgent fix.
