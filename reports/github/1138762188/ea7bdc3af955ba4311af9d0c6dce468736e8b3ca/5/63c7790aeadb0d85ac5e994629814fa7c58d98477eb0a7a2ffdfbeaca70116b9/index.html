JavaScript analysis reported javascript.xray.unsafe-regex

Minor caution · medium confidence

The flagged pattern-matching code comes from libraries bundled into the release. Nothing shown can be abused beyond briefly slowing the user's own chat window, which is a minor quality issue rather than a security harm.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The regex literals visible in the bundled output are fixed lexer alternations and bounded value validators from vendored parsing and templating libraries, and the scanner retained no matched values showing a catastrophic-backtracking pattern. Theoretical pathological input would only stall the user's own tab, which is a recoverable low-impact condition under this threat model.

Impact: low · Exploitability: unlikely

JavaScript analysis reported javascript.xray.obfuscated-code

Minor caution · medium confidence

The extension ships a compressed, machine-generated version of its code, which scanners often mistake for deliberate obfuscation. The visible parts are readable and match the project's stated features, so this looks like normal build output.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.obfuscated-code. The match applies to this repository.

Contextual assessment: The file is a generated, minified production bundle (file_role generated, transform depth 1), so dense mangled code triggers the obfuscation heuristic. The supplied imports and API calls use readable strings and named host modules, and the surrounding repository publishes source and README, which is inconsistent with deliberate concealment. The practical weakness is reduced reviewability of the shipped artifact, not demonstrated hidden behavior; scanner confidence is low.

Impact: low · Exploitability: unlikely

Developer action: Publish or retain an unminified build or source map so the shipped bundle can be more easily reviewed by the community.

JavaScript analysis reported javascript.xray.unsafe-regex

Minor caution · medium confidence

Some text-matching patterns in included parser libraries could in theory be slow on weird input, but the input comes from the user's own chats and files, so the worst case is a brief slowdown in your own session.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex. The match applies to this repository.

Contextual assessment: The flagged regexes are tokenizer and numeric/date validation patterns inside bundled parsing libraries (template tokenizer, XML parser, JSON path checks) and tracker markdown-fence extraction. Most are linear; the XML tag-matching pattern with backreferences could backtrack on adversarial input, but inputs derive from the user's own model responses and local files, and the worst demonstrated effect would be a slow parse in the user's own tab — a recoverable local slowdown, not meaningful concrete harm. No attacker-controlled remote path to these regexes is demonstrated.

Impact: low · Exploitability: unlikely

Developer action: Consider updating bundled parser dependencies to current versions during the next build; no urgent change required.
