Gitleaks reported generic-api-key

Material concern · medium confidence

The app includes a secret access token directly in its front-end code. Since that code is sent to everyone who installs the app, anyone can copy the token and use the app's account with the JannyAI service for their own purposes, which could lead to the token being blocked or abused.

Technical evidence

Scanner reason: Gitleaks matched secret-detection rule generic-api-key in this repository.

Contextual assessment: A hardcoded token is embedded in a frontend production file as a fallback for the JannyAI discovery provider. Because this file ships to every client, the token is trivially extractable from the built application. Any user or third party can recover it and use it to access the JannyAI search endpoint outside the app's intended flow, potentially causing rate-limit exhaustion, quota abuse, or revocation of the token for all legitimate users. There is no per-user credential here; it is a shared secret baked into client code.

Impact: medium · Exploitability: plausible

Developer action: Remove the hardcoded fallback token from client-side code. Obtain the JannyAPI token through a server-side proxy, a user-supplied configuration value, or an ephemeral token-exchange flow so that no shared credential is shipped in the built application.
