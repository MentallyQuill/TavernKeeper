JavaScript analysis reported javascript.xray.unsafe-regex

Minor caution · medium confidence

A pattern used to find and hide API keys and passwords in chat text might be slow on purposefully crafted messages, which could temporarily freeze the page.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.unsafe-regex in this repository.

Contextual assessment: Line 47 defines PROVIDER_PROMPT_SECRET_ASSIGNMENT_PATTERN, a complex regex used in the scrubProviderPromptSecrets redaction function to detect and redact secret-like assignments (apiKey, authorization, bearer, etc.) from user-supplied text before sending prompts to providers. The regex contains nested alternations and lazy quantifiers (["'][^"']*"|'[^']*'|Bearer\s+[\s\S]*?|[\s\S]*?) that can cause catastrophic backtracking on crafted input, potentially leading to a client-side denial of service (browser hang or slowdown). While the project includes extensive test coverage for redaction behavior (test-cards.mjs), the regex itself operates on untrusted chat data and character card content, making ReDoS exploitation plausible. The concrete harm is limited to local recoverable denial of service (frozen tab, increased CPU) which is low impact.

Impact: low · Exploitability: plausible

Developer action: Consider replacing the regex with a simpler parsing approach or adding a backtracking limit. For example, process text character by character or use a library that limits catastrophic backtracking. The extensive existing test suite can validate that redaction behavior remains correct.
