Related contextual observations

Client secret embedded in client-side bundle

low risk · high confidence

The Google app secret is compiled into the plugin, meaning anyone who inspects the built file can extract it. While this does not by itself let an attacker access user data, it is a non-standard practice for browser-based apps. A more appropriate method called PKCE exists that avoids needing a secret at all.

Technical assessment

CLIENT_SECRET is read from import.meta.env.VITE_GOOGLE_CLIENT_SECRET and used in the authorization code exchange (line 124) and refresh token flow (line 155). Because this is a client-side Vite-built plugin, the secret is embedded in the shipped JavaScript bundle and is extractable by any user. For browser-based or installed-app OAuth2 clients, Google recommends using PKCE instead of a static client secret. This is a design weakness, not evidence of malicious exfiltration: the secret is used only in requests to Google's own token endpoint.

Impact: low · Exploitability: plausible

Developer action: Consider migrating to the OAuth2 PKCE flow (authorization code with PKCE) for this client-side application, which eliminates the need to embed a client secret in the browser bundle. Google supports PKCE for installed and web applications.
