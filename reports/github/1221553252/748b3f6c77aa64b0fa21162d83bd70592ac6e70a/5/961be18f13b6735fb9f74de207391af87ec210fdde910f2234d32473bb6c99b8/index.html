Expected behavior · high confidence

This is a documentation file describing how the extension works, not the working code itself. What it describes is normal: if you choose to use your own AI service, the extension saves the key you type in and sends it only to the service address you chose, for your own requests. The key is not sent anywhere hidden or to the developer, and it stays in your browser.

Technical evidence

Scanner reason: A credential source and an outbound network operation were detected in the same file.

Contextual assessment: The flagged file is technical documentation, not executable code, so no runtime data flow exists at this location. The described design is that a user-configured custom OpenAI-compatible backend sends the user's own API key as a Bearer credential only to the endpoint URL the user explicitly configured in the extension settings, and that key is kept in browser-local storage rather than in synced extension settings or chat metadata. The network destination and the credential source are both user-chosen and user-visible, the key is not routed to any hardcoded or third-party destination, and the default backend path goes through the host SillyTavern connection rather than a custom endpoint at all. This matches the documented purpose of an extension that performs its own LLM analysis calls and is the standard pattern for a bring-your-own-endpoint feature.
