JavaScript analysis reported javascript.xray.shady-link

Expected behavior · high confidence

The scanner flagged a link that uses a javascript: address, which can sound alarming. Here it is a hardcoded, empty placeholder used to make a 'Show all' text look like a clickable link; the real behavior is a local click handler that expands text on the page. No code is injected, nothing leaves the browser, and the string is fixed in the source rather than coming from chat content or any untrusted source.

Technical evidence

Scanner reason: JavaScript analysis matched static JavaScript security signal javascript.xray.shady-link. The match applies to this repository.

Contextual assessment: The flagged literal is a static, empty javascript: URI assigned to an anchor's href so it renders as a clickable 'Show all' control inside the extension's prompt-inspector UI. The URI is a constant string in the shipped code, not derived from model output, chat content, or any untrusted input, so it cannot be used to execute attacker-chosen script. The attached click handler calls preventDefault and replaces clipped text with the full text locally; there is no navigation, no network request, and no data leaving the page. All message content in this UI path is rendered via textContent, not innerHTML, except for two hardcoded icon fragments, so model-generated content is not interpreted as markup. The scanner rule is a keyword heuristic on the javascript: scheme and does not demonstrate exposure in this data flow.

Impact: none · Exploitability: unlikely

Developer action: Optional cleanup: replace the anchor with a styled button element (or set role/tabindex on a span) and drop the javascript: URI entirely; this avoids tripping strict Content-Security-Policy configurations that forbid javascript: navigation and removes the scanner signal.
