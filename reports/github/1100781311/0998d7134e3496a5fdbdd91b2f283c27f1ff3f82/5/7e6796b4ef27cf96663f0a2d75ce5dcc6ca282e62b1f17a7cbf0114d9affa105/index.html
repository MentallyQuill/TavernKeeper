Contextual expected matches (2)

Gitleaks reported generic-api-key

Expected behavior · medium confidence

The extension carries a Google sign-in credential so it can finish its own Google login. That credential is only ever sent to Google's own login service, which is the normal way desktop-style apps do this; Google does not consider this kind of credential secret. The code never sends it anywhere else, and no user passwords or unrelated accounts are involved.

Technical evidence

Scanner reason: Gitleaks matched secret-detection rule generic-api-key. The match applies to this repository.

Contextual assessment: The flagged constant is an OAuth client secret for the Google sign-in this provider extension implements. The supplied code uses it only in the authorization-code exchange and refresh-token requests, both sent exclusively to Google's official OAuth token endpoint, together with a PKCE code challenge and a local loopback redirect. That combination is Google's documented installed-application pattern, in which the client secret is not treated as confidential and is expected to ship inside the distributed application. The matched value was withheld from review, so it cannot be confirmed as a live credential, and no destination other than Google appears anywhere in the supplied flow. Same-file presence of a credential literal is not, by itself, evidence of exposure to harm.

Impact: none · Exploitability: unlikely

Developer action: Confirm the Google OAuth client is registered as a desktop or installed application, where Google treats the embedded secret as public; if it was instead registered as a web application, treat the published value as compromised and rotate it.

Credential access and network transmission in one file

Expected behavior · high confidence

The extension reads your Google login token and sends it to Google's own service to confirm who you are and to renew the token when it expires. That is exactly what the token is for, and it never goes to anyone other than Google.

Technical evidence

Scanner reason: A credential source and an outbound network operation were detected in the same file.

Contextual assessment: The heuristic paired credential reads with a network call in one file. The access token is read from the extension's own storage and sent only as a bearer header to Google's own userinfo endpoint, and the refresh token is sent only to Google's OAuth token endpoint for renewal. Those are the tokens' intended destinations for the Google-backed provider this project states it is, and every outbound request in the supplied source targets Google. No third-party endpoint, log sink, storage write, or other recipient receives the tokens, so the correlation the scanner flagged is the legitimate operation of the login flow rather than exfiltration.

Impact: none · Exploitability: unlikely

Developer action: none

Related contextual observations

OAuth state value is generated but never validated when the user pastes the callback URL

low risk · medium confidence

The plugin creates a one-time marker when it sends you to Google's login page, but it never checks that marker when you paste the result back. Checking it would make it much harder for someone to trick you into connecting the wrong person's account.

Technical assessment

The login flow generates a random state parameter and includes it in the authorization URL, but when the user pastes the redirect URL back, only the authorization code is extracted and the state is never compared. The PKCE verifier limits classic code-injection risk, and the paste-based design requires the user to actively supply the callback URL, so no concrete harm is demonstrated. Still, a user who could be persuaded to paste an attacker-supplied callback URL would bind the attacker's account tokens into the plugin, and state comparison would close that gap.

Impact: low · Exploitability: unlikely

Developer action: Compare the state value found in the pasted callback URL against the locally generated state before exchanging the authorization code, and reject mismatches.
