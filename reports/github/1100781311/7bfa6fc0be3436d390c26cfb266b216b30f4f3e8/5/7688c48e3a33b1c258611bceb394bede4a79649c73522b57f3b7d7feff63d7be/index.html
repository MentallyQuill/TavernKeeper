Minor cautions

Gitleaks reported generic-api-key

Minor caution · medium confidence

The code includes a Google login secret directly in its source. Because this is a desktop or browser-extension style login, Google does not treat this particular secret as truly private, and the code also uses a separate security mechanism (PKCE) to protect the login flow. It is still better practice to avoid hardcoding secrets, but this is not a serious security hole.

Technical evidence

Scanner reason: Gitleaks matched secret-detection rule generic-api-key. The match applies to this repository.

Contextual assessment: Detailed technical wording was omitted by the public report safety filter.

Impact: low · Exploitability: unlikely

Developer action: Consider using Google's client-side OAuth flow that does not require a client secret, or document why embedding this native-app client secret is acceptable for your OAuth client type. Rotate the secret in the Google Cloud Console if you suspect it has been exposed.

Contextual expected matches (1)

Credential access and network transmission in one file

Expected behavior · high confidence

The code reads stored login tokens and sends them to Google's own servers to authenticate the user and fetch their profile. This is exactly what a Google login module is supposed to do. There is no sign of tokens being sent anywhere other than Google.

Technical evidence

Scanner reason: A credential source and an outbound network operation were detected in the same file.

Contextual assessment: The scanner flagged co-location of credential access and network calls in the same file. Examining the actual data flows: access tokens retrieved from RisuAPI storage are sent exclusively to Google's userinfo endpoint as Bearer authorization headers, the OAuth authorization code and client secret are sent exclusively to Google's OAuth2 token endpoint for code exchange, and refresh tokens are sent exclusively to the same Google token endpoint for refresh. All destinations are legitimate Google APIs required by the stated project purpose of authenticating with Google Antigravity. There is no evidence of tokens being transmitted to any third-party, non-Google, or unexpected destination. The credential handling matches what an OAuth authentication module is expected to do.

Impact: none · Exploitability: unlikely
