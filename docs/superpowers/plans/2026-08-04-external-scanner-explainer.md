# External Scanner Explainer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand TavernKeeper's public landing-page "How it works" section with accurate descriptions, usage notes, and official repository links for its five external scanners.

**Architecture:** Keep the existing static landing-page renderer and four-step process. Add a static scanner metadata collection and render a responsive card grid beneath the process, with copy grounded in the configured scanner adapters and conditional applicability rules.

**Tech Stack:** TypeScript, Vitest, static HTML/CSS generated by `src/site/render-landing.ts`.

## Global Constraints

- Cover only externally maintained scanners: Gitleaks, OpenGrep, OSV-Scanner, zizmor, and malcontent.
- Link each tool name to its official GitHub repository.
- Describe specialized coverage without claiming any scanner proves intent, catches every vulnerability, or certifies a repository.
- Preserve the existing exact-commit, untrusted-data, non-execution, and advisory-report limitations.
- Do not change scanner execution, report schemas, or generated report contracts.
- Leave the unrelated nested `TavernKeeper/` tree untouched.

### Task 2: Render the external scanner explainer

**Files:**
- Modify: `src/site/render-landing.ts`
- Test: `tests/site-presentation.test.ts`

**Interfaces:**
- Consumes: static scanner metadata, existing site styles, and `renderLandingHtml()`.
- Produces: A responsive `#external-scanners` subsection with five linked scanner cards and preserved advisory boundaries.

- [ ] **Step 1: Define static scanner metadata beside the landing renderer**

Create a typed constant with one entry per external scanner. Each entry must include `name`, `url`, `what`, and `usage` copy. Ground the usage text in the current runtime:

```ts
const EXTERNAL_SCANNERS = [
  {
    name: "Gitleaks",
    url: "https://github.com/gitleaks/gitleaks",
    what: "Searches source and repository history for exposed secrets and credential-like values.",
    usage: "TavernKeeper runs the pinned scanner against the exact commit and its bounded history as data.",
  },
  // OpenGrep, OSV-Scanner, zizmor, and malcontent follow the same shape.
] as const;
```

Use wording that accurately distinguishes OSV-Scanner dependency inputs, zizmor workflow inputs, and malcontent applicable artifacts from the always-invoked Gitleaks/OpenGrep sequence.

- [ ] **Step 2: Add the renderer and styles**

Add a small renderer for the metadata entries and insert it below the existing ordered steps. Use semantic markup:

```html
<section class="scanner-section" id="external-scanners" aria-labelledby="scanner-title">
  <div class="section-heading">...</div>
  <div class="scanner-grid">...</div>
</section>
```

Each card should use an `<article>`, a heading containing an external link, and separate paragraphs for what the scanner detects and how TavernKeeper uses it. Add responsive CSS to the existing landing styles: a two-column grid on wider screens and one column below the existing mobile breakpoint. Preserve the current four-step list and boundary section.
