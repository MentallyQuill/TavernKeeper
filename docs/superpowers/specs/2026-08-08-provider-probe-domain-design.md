# Provider Probe Domain Design

The automatic circuit represents shared provider availability, not the success
of every possible contextual assessment. A direct probe that returns a
sanitized target-domain failure has proven endpoint, authentication, transport,
and model invocation are available. It therefore clears the shared hold; the
same target-domain failure may still be charged to an individual repository if
it occurs during that repository's scan.

Shared, security, malformed, inconsistent, and missing probe failures continue
to advance the automatic hold. A typed validator accepts only the allowlisted
target-domain contextual-model tuples, and the workflow call to that validator
is pinned by policy.

A manual reconciliation may request one forced direct probe while a hold is
cooling. This does not clear or mutate the hold by itself and accepts no target,
provider, endpoint, model, or credential input. It only bypasses the hold's
timer for the existing trusted provider configuration, allowing a deployed
recovery fix to be exercised immediately.
